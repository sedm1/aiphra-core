# Как читать модуль CalDAV

Этот модуль читает свойства ресурсов через HTTP-запросы и получает ответы в XML.
У пользователя на сервере есть адрес, по которому можно узнать папки с его календарями.
Сами календари тоже имеют URL.

## С чего начать в коде

[Client.php](../../packages/caldav/src/CalDav/Client.php) подключает операции через traits
и создаёт общее HTTP-соединение. Публичные методы клиента — `calendars()` и `calendar($id)`.
В приложении можно использовать `Providers\CalDav\Provider` с общими фильтрами Aiphra.

Чтение списка календарей разбито на следующие шаги:

1. [GetCalendars.php](../../packages/caldav/src/CalDav/Internal/Calendars/GetCalendars.php)
   задаёт последовательность: найти папки, прочитать календари, убрать повторы.
2. [FindCalendarFolders.php](../../packages/caldav/src/CalDav/Internal/Discovery/FindCalendarFolders.php)
   спрашивает сервер об адресах папок. Если сервер сообщил только адрес пользователя,
   повторяет вопрос по этому адресу.
3. [ReadCalendarProperties.php](../../packages/caldav/src/CalDav/Internal/Calendars/ReadCalendarProperties.php)
   читает тип и имя ресурсов в папке, выбирает календари и создаёт обычные `Calendar` DTO.

Для известного ID работает отдельный
[GetCalendar.php](../../packages/caldav/src/CalDav/Internal/Calendars/GetCalendar.php):
он читает один URL напрямую. Поиск пользователя и его папок здесь не нужен.

В провайдере общий [CalendarList](../../packages/core/src/Providers/Concerns/CalendarList.php)
применяет фильтры и диапазон к ленивому списку. Он прекращает чтение после достижения
лимита, поэтому клиент не запрашивает следующие папки. [Примеры запросов](QUERIES.md).

## Что означают слова протокола

| Термин в XML или HTTP | Смысл |
| --- | --- |
| `PROPFIND` | HTTP-метод чтения свойств ресурса. Само содержимое событий он здесь не загружает. |
| `Depth: 0` | Прочитать свойства только указанного адреса. |
| `Depth: 1` | Прочитать свойства адреса и его непосредственных дочерних ресурсов. |
| `current-user-principal` | Ссылка на ресурс текущего авторизованного пользователя. |
| `calendar-home-set` | Ссылки на папки, в которых нужно искать календари пользователя. |
| `resourcetype` | Тип ресурса. Вложенный `calendar` отличает календарь от обычной папки. |
| `displayname` | Имя календаря. |
| `href` | Ссылка, иногда относительная. В PHP она преобразуется в полный URL. |
| `207 Multi-Status` | Один HTTP-ответ с результатами для нескольких ресурсов и свойств. |
| `propstat` | Группа свойств с одинаковым статусом чтения. `404` здесь означает отсутствие свойства. |

## Общая работа с HTTP и XML

[ReadProperties.php](../../packages/caldav/src/CalDav/Internal/ReadProperties.php)
формирует `PROPFIND`, отправляет его и передаёт ответ в
[ResponseParser.php](../../packages/caldav/src/CalDav/Internal/Xml/ResponseParser.php).
Парсер проверяет HTTP- и XML-статусы и возвращает объекты
[Resource](../../packages/caldav/src/CalDav/Internal/Xml/Resource.php): адрес ресурса и его свойства.
Он не выбирает календари и не создаёт DTO календарей или событий.

[UrlResolver.php](../../packages/caldav/src/CalDav/Internal/UrlResolver.php)
превращает относительные ссылки в полные адреса, обрабатывает `.` и `..`
и проверяет, что протокол, хост и порт остались теми же.

Всё в `Internal` — детали реализации с пометкой `@internal`, без гарантий совместимости
для внешнего кода. PHP технически разрешает обращаться к этим классам; приложению
следует использовать провайдер или `Client`.

## Как добавлять операции

У каждой операции свой файл. Получение событий, создание и удаление будут добавляться
отдельными traits в `Internal/Events/` и подключаться в `Client`. Это место для будущих
реализаций; сейчас таких операций нет.

Разбор полей событий будет находиться рядом с операциями событий. Общий XML-парсер
и файлы получения календарей не должны получать ветки для новых операций.
